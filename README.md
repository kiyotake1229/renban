## コンセプト（Twitterの連番募集に勝つための差別化）
- スワイプで人を選ぶのではなく、**公演を選んでから、その公演に行く人を探す**
- **18項目の条件設定**（性別・年代・未成年除外・本人確認・FC・参戦回数・連番経験・初心者・推し一致・相手のチケット・受け渡し方法・物販・声出し・終演後・遠征・ホテル・車）
  - 標準の条件と、公演ごとの条件を分けて持てる
  - 条件を満たさない人も「一致率順」に表示し、満たさない項目を打ち消し線で表示
  - 条件を保存すると、合う人が新しく募集を始めたときに通知（デモでは8秒後に1人現れる）
  - 性別を「回答しない」にしている人には、同性条件を適用しない
- 自分の募集内容（枚数・席種・受け渡し方法）も構造化して相手に見せる
- **公演検索**：フリーワード（アーティスト・ツアー・会場・フェス出演者）＋ ジャンル / 内容（ワンマン・ツアー・フェス・リリイベ・ファンミ・対バン）/ 時期 / エリア / 会場タイプ / 募集あり / 譲れる人あり。並び替えは日付・募集人数・条件に合う人が多い順
- 検索条件は保存でき、ホームに件数つきで並ぶ（新着に気づける導線）
- **毎日開く理由（日常化）**：ホーム上部に「次の現場まであとN日」のカウントダウンと、推しの予定（先行締切・当落発表・リリース・配信・TV・一般発売）。締切3日以内は強調
- **お知らせ（ベル）**：申請の到着、承諾・見送り、成立、条件に合う人の出現、ありがとうの受信を一覧で残す。タップで該当の公演へ
- **X（Twitter）連携（API不要の範囲）**
  - 公演ページ「投稿」：募集内容と条件を定型文にして X の投稿画面を開く（Web Intent。APIキー不要・無料）。アプリのリンク（公演ページ直リンク `#ev=公演ID`）とハッシュタグ入り。ポップアップが開けない環境では文面を自動でコピーして案内
  - マイページ「募集文から取り込む」：X の募集文を貼ると、公演・枚数・席・受け渡し・条件を自動認識して参戦予定と条件に反映
  - 人物カード・シートに「X連携済（フォロワー数・利用歴）」を信頼の材料として表示（デモではモック。本番は Xでログイン）
  - X からの読み取り（ハッシュタグ監視など）は API が有料（月$200〜）のため未実装。方針は「X に出して呼び込む」
- **終演後の流れ**：成立した公演のページに「終演した」ボタン。連番相手に「ありがとう」（5段階＋ひとこと）を送ると、その公演が手帳に移り、数秒後に相手からもありがとうが返ってくる（デモ）。ありがとう数は信頼スコアに加算
- **手帳**：参戦履歴に満足度・席・連番相手・費用（チケット/交通/宿/物販）・セトリ感想メモを記録。今年の参戦回数・費用合計・いちばん行った推しを集計。履歴は連番の実績としても使う設計
- 信頼の見える化：参戦回数・連番回数・ありがとう数・本人確認
- 安心設定：同性のみ表示（マイページのトグル。標準条件の「性別」と連動）、通報・ブロック（人物シートから。理由5種＋詳細。ブロックすると一覧・申請から消える）
- 成立後は「当日メモ」（集合場所・時間・チケット受け渡し・チェックリスト）で当日の段取りを共有

## 性別・経験に合わせた初期設定（v9）
見た目を性別で変えるのではなく、**安心の初期値と画面の順番**を変える。あとからマイページで全部変えられる。
| 選択 | 相手の条件の初期値 | 検索の並び | ホームの順番 |
|------|-------------------|-----------|-------------|
| 女性 | 同性のみ・本人確認済のみ・未成年除外 | 日付順 | 「条件に合う人」をカウントダウンの直後に |
| 男性 | 推し一致・物販一緒に（本人確認や参戦回数の条件は外す） | 募集人数順 | 「募集を X に出す」を直後に、「条件に合う人」は参戦予定の後 |
| 回答しない | 標準 | 日付順 | 女性と同じ |
| 連番が初めて | 上に加えて「連番経験1回以上の人」 | | |
- 初回案内の4ステップ目で選ぶ。マイページで性別を変えたときも初期値を入れ直す
- 「条件に合う人」は参戦予定の公演を横断して一致率の高い3人を出し、タップで人物シートへ
- **ペンライトの色**：アンバー／ピンク／ブルー／グリーンをマイページで選ぶと、アプリの差し色（ボタン・タブ・強調）が変わる。性別と紐づけず「推しの色」として選ぶ

## デモの動き
- 起動時に2件の申請が届いている（承諾すると即成立）。お知らせにも2件入っている
- 自分から申請すると、数秒後に相手が承諾（一部のユーザーは見送る）
- 成立するとトークに相手から最初のメッセージが届く。こちらの発言のキーワード（物販・集合・終演後・チケット・セトリ・遠征）に合った返信を、その人の持ちネタから選ぶ（同じ返信は繰り返さない）
- 成立した公演で「終演した」を押すと、ありがとう送信 → 手帳に記録 → 6秒後に相手からありがとうとメッセージが届く
- **日付は開いた日に追従する**：基準日（2026-09-14）より後に開くと、公演・予定・履歴の日付が同じ日数だけ後ろにずれる。いつ開いても「次の現場まであと13日」のような生きた画面になる
- データは localStorage のみ。通信なし

## デザイン（v8）
- 「半券」を軸にした画面。会場の暗がり（地）に、紙のチケット（公演カード・手帳・初回案内）とペンライトの色だけが浮かぶ
- 書体：本文 BIZ UDPGothic（案内表示で使われる読みやすい書体）、見出し・数字 Bricolage Grotesque、日付・時刻・番号 IBM Plex Mono（チケットの印字）
- 公演カードは実際のチケットの慣習に合わせて OPEN / START / 席種を等幅で印字し、ミシン目と切り欠きを入れた

- ライト／ダーク両対応。文字サイズは本文 15px、補足 13px 以上、タブ 11.5px を下限にし、実機幅（390px）で折り返しを確認済み

## 技術メモ
- `prompt()` / `confirm()` は Artifact のサンドボックス内で動かないため、すべてアプリ内のシート（`askDialog`）に置き換え済み
- X投稿の `window.open` が塞がれている環境では、文面をクリップボードにコピーしてトーストで案内する
- X投稿に入るリンクは GitHub Pages のURL。公演ページ直リンク（`#ev=e1`）もそこで動く
- iPhone で使うときは Safari で GitHub Pages のURLを開き、共有メニュー →「ホーム画面に追加」。フルスクリーンで起動し、オフラインでも動く
- 更新の流れ：`index.html` を直す → `git add -A && git commit -m "..." && git push` → 1〜2分で GitHub Pages に反映。Artifact は別途公開し直す
- Esc キーでシート・成立画面を閉じられる。各シート右上に閉じるボタンあり

## 収益モデルの仮説
連番に特化しているからこそ取れる導線。どれもユーザー間の金銭授受は挟まない。
| 案 | 内容 | 向いている理由 |
|----|------|----------------|
| 本人確認バッジ（有料） | 身分証確認で「本人確認済」表示。条件で「済みのみ」に絞る人が多いほど価値が上がる | 安全を買う動機が明確。月額ではなく1回課金で始めやすい |
| プレミアム（月額） | 条件の保存数・お知らせの優先配信・「条件に合う人が多い順」など探す側の機能を強化 | 遠征組・全通勢は現場数が多く、探す回数も多い |
| 遠征アフィリエイト | 手帳の費用欄と参戦予定から、会場近くのホテル・新幹線・高速バスを提案 | 遠征の予定と日程がアプリ内にすでにある。連番相手とホテルシェアの導線にもなる |
| 公式・主催者向け | 公演の公式登録、FC限定の連番募集枠、来場者の傾向データ（匿名） | 主催側にも「安全な連番」は転売対策として価値がある |
| チケットサイト送客 | 「チケットなし」の人に一般発売・リセールの公式リンクを出す | 公式リセールへの送客は転売対策と両立する |
