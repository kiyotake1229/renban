## 仕様

### 画面と機能

画面は下のタブ5つ（現場 / さがす / 申請 / トーク / マイページ）と、その上に重なる公演ページ・チャット・各種シートでできている。幅は最大 430px のスマホ向け。ライト／ダーク両対応。

**初回案内**（`#intro`、`INTRO` `renderIntro` `openIntro` `closeIntro`）
- 初回だけ4ステップの案内が出る。1〜3枚目は使い方、4枚目で「性別」と「連番の経験」を選ぶ
- 「スキップ」を押すと4枚目に飛ぶ。初期設定の選択は飛ばせない
- 「この設定ではじめる」で `applyPreset` を実行し、`S.onboarded` を true にする
- マイページ「使い方をもう一度見る」で再表示できる

**性別・経験による初期設定**（`PRESETS` `applyPreset` `DEFAULT_COND`）
- 見た目は変えない。変えるのは「相手の条件の初期値」「検索の並び順」「ホームの並び順」
- 実際の条件は `DEFAULT_COND` の上に `PRESETS` の値を重ねたもの（`condFor`）。`DEFAULT_COND` は「未成年除外・本人確認済のみ・参戦3回以上・推し一致・物販一緒に並ぶ・声出し全力」

| 選択 | 実際に効く相手の条件 | 検索の並び | ホーム（`S.homeFocus`） |
|------|---------------------|-----------|------------------------|
| 女性 | 同性のみ＋`DEFAULT_COND` の6項目 | 日付順 | `people`：カウントダウンの直後に「条件に合う人」 |
| 男性 | 未成年除外・推し一致・物販一緒に並ぶ・声出し全力（本人確認・参戦回数は外す） | 募集人数順 | `post`：直後に「募集を X に出す」、「条件に合う人」は参戦予定の後 |
| 回答しない | `DEFAULT_COND` のまま | 日付順 | `people` |
| 連番が初めて | 上に加えて「連番の経験1回以上」 | — | — |

- マイページで性別を変えて保存したときも `applyPreset` が走る

**現場タブ**（`#s-home`、`renderHome`）
- 右上: エリア表示（`S.me.area`、初期値「関東」）とお知らせのベル（`#b-notif`）
- 上部の切り替え（`#home-seg`）で「これから」と「手帳」を切り替える（`S.homeView`）
- 「これから」に並ぶもの（上から）
  - カウントダウン: 参戦予定のうち一番近い公演まであと何日か。タップで公演ページ
  - 条件に合う人: 参戦予定の公演を横断して一致率の高い3人（`topPeople`）。タップで公演ページと人物シート
  - 募集を X に出す: 相手をさがし中の公演がある場合だけ出る（`#b-home-xpost`）
  - 推しの予定: `SCHEDULE` のうち自分の推しで今日以降のもの。4件まで表示し、残りは「あとN件を見る」。締切まで3日以内は強調
  - 参戦予定: 半券型のカード（`ticketHTML`）。状態は「連番確定」「申請が届いています」「申請中」「相手をさがし中・条件に合うN人」
  - 保存した検索: 名前と該当件数。タップで検索条件を復元、×で削除
- 「手帳」（`renderDiary` `openDiary`）
  - 集計: 今年の参戦回数、記録した費用、いちばん行った推し
  - 参戦履歴: 埋め込みの過去公演 `PAST` と、終演処理した公演（`S.done`）
  - 記録シート: 満足度（5段階）、席・整理番号、連番相手（成立した相手から候補表示）、費用（チケット・交通・宿・物販）、セトリ・感想メモ（400字）

**さがすタブ**（`#s-search`、`renderSearch` `searchEvents`）
- フリーワード: アーティスト名・ツアー名・会場・都市・ジャンル・内容・フェス出演者（`lineup`）を対象に部分一致
- 絞り込み: ジャンル（`GENRES`、7種）、内容（`KINDS`、6種）、時期（`PERIODS`：すべて・今週・今月・来月・3か月以内・2か月後の月・3か月後の月）、エリア（`REGIONS`、6種）、会場タイプ（`VTYPES`、5種）、「連番募集あり」「譲れる人がいる」
- 並び替え: 日付順 / 募集人数順 / 条件に合う人が多い順
- 今日より前の公演は出ない
- 「保存」で名前をつけて `S.savedSearches` に保存し、ホームに並ぶ。「条件をクリア」で初期化

**公演ページ**（`#p-event`、`openEvent` `renderEvent` `personHTML`）
- 公演情報（日付・開場／開演・会場、フェスは出演者）
- 自分の状態で表示が変わる
  - 参戦予定でない: 「行く」で参戦予定に入る（チケットなし扱い）
  - 参戦予定: 自分の募集内容と「編集」（`openMyTicket`：チケット3種・席種・席の補足・受け渡し方法、参戦予定から外す）、「投稿」（`openXPost`）
  - 連番成立済み: 「終演した → ありがとうを送って手帳に記録（デモ）」ボタン（`#b-finish`）
  - 終演済み: 「手帳を見る」
- 条件バー: いまの条件の一覧、「この公演だけ」の表示、「条件を変える」（`openCond`）、「条件をすべて満たす人だけ表示」（`S.onlyMatch`）
- 人の一覧: その公演のチケット情報を持つ架空ユーザー。一致率の高い順、同率なら連番回数の多い順
  - 各カード: 条件一致数（例 5/6）、参戦・連番・ありがとう回数、FC会員、X連携（フォロワー数）、推し一致、満たさない条件（打ち消し線、`.miss`）、自己紹介、チケットの状況
  - 操作ボタン: 「連番を申請」「取り消す」「確認する」（届いた申請へ）「トーク」
- 右上に「連番募集 N人」

**相手の条件**（`CONDS` `COND_GROUPS` `openCond` `scoreUser`）
- 18項目を3グループで設定する
  - 相手について: 性別、年代（下限）、年代（上限）、未成年、本人確認、ファンクラブ、参戦回数、連番の経験、連番初心者、推し
  - チケット: 相手のチケット、受け渡し方法
  - 当日の過ごし方: 物販、声出し、終演後、遠征、ホテル、移動（車）
- 「問わない」「どちらでも」以外の項目だけで判定する
- 自分の性別が「回答しない」のときは、性別の条件は常に満たす扱い
- 保存先は2つ。標準の条件（`S.cond.default`）と、公演ごとの条件（`S.cond.byEvent`）。公演ページから開いたときは「この公演だけに適用する」で選ぶ
- 「初期値に戻す」は `DEFAULT_COND` に戻す
- 保存すると、デモとして8秒後に「条件に合う人が新しく募集を始めた」通知が出ることがある（下の「デモの自動動作」参照）

**人物シート**（`#sh-person`、`openPerson`）
- 参戦・連番・ありがとうの回数、X連携の有無（フォロワー数・利用歴）、推し、スタイル、自己紹介、その人の参戦予定
- 状態に応じて「トークを開く」「連番を申請」「閉じる」
- 下部に「通報・ブロック」

**申請タブ**（`#s-req`、`renderReq` `openApply` `respond`）
- 届いた申請: 起動時に2件（しゅん／横浜アリーナ、りん／Zepp Haneda）。「承諾して連番にする」で即成立、「見送る」で消える
- 送った申請: 状態（返事待ち・承諾・見送り）。返事待ちは「取り消す」、承諾は「トークを開く」
- 申請シート: メッセージ欄と定型文4種（`APPLY_TPL`）
- タブのバッジは、申請タブを一度開くと消える（`S.seenReq`）

**連番成立**（`#match`、`createMatch`）
- 「連番成立」の全画面表示。「トークで当日の相談をする」か「あとで」
- 自分がチケットなしで、相手が2枚持ちなら、自分の参戦予定を「1枚持ち」に変える
- お知らせに成立を記録し、数秒後に相手から最初のメッセージが届く

**トーク**（`#s-talk` `#p-chat`、`renderTalk` `openChat` `renderChat`）
- 一覧: 成立した相手ごと。最後の発言が新しい順。未読数と「入力中…」を表示
- チャット画面
  - 定型文5種（`QUICK`）、スタンプ8種（`STAMPS`、線画SVG）
  - Enter で送信。日本語の変換中は送らない
  - 自分の発言には、相手が返信を書き始めた時点で「既読」が付く
  - 相手は発言のキーワードに合った返信を、その人の持ちネタ（`USERS[].replies`）から選ぶ。スタンプにはスタンプで返す
  - 右上メニュー（`#b-chat-menu`）: プロフィールを見る、当日メモを開く、通報・ブロック
- 当日メモ（`#notebar` `#sh-note`、`renderNoteBar`）: 集合時間、集合場所、チケットの受け渡し（未定・自分が2枚・相手から1枚・それぞれ1枚）、チェックリスト5項目（`CHECKS`）

**終演後の流れ**（`#sh-finish`、`openFinish`）
1. 成立済みの公演ページで「終演した」を押す
2. 満足度（初期値5）とひとこと（60字）を入れて「ありがとうを送る」
3. その公演を `S.done` と手帳（`S.diary`）に記録する。参戦予定・募集内容・公演ごとの条件からは消す
4. 手帳に切り替わり、記録シートが開く
5. 6秒後に相手から「ありがとう」とメッセージが届き、自分のありがとう数が1増える

**お知らせ**（`#b-notif` `#sh-notif`、`notify` `openNotif`）
- 記録するもの: 起動時の申請2件、連番成立、見送り、条件に合う人の出現、ありがとうの受信
- 最新30件まで。開くと全部既読。公演に紐づくものはタップで公演ページ

**X連携**（`APP_URL` `xPostText` `openXPost` `parseXPost` `openXImport` `XLINK`）
- 投稿: 募集内容と条件（最大5つ）を定型文にし、X の投稿画面（Web Intent）を開く
  - 文面にはアプリの公演ページ直リンク（`https://kiyotake1229.github.io/renban/#ev=公演ID`）と、ハッシュタグ（#連番募集 #連番 #アーティスト名 #レンバン）が入る
  - 画面が開けない環境では、文面をクリップボードにコピーして案内する。「コピー」ボタンもある
  - 入口: 公演ページの「投稿」、ホームの「募集を X に出す」
- 取り込み: マイページ「募集文から取り込む」
  - X の募集文を貼ると、公演（アーティスト名・会場・都市・日付から推定）、枚数、席、受け渡し方法、条件（同性・本人確認・FC・未成年・物販・声出し・終演後・遠征・初心者・ホテル）を読み取る
  - 公演が特定できたときだけ「この内容で参戦予定と条件を設定」を押せる。条件は公演ごとの条件として保存する
  - 「サンプルを入れる」で例文（`xSample`）が入る
- 連携表示: 架空ユーザー11人に「X連携済（フォロワー数・利用歴）」を表示。値は `XLINK` の固定値。マイページの「Xのユーザー名」は表示に使うだけ
- 直リンク: 起動時に URL の `#ev=e数字`（または `?ev=`）を見て、その公演ページを開く
- X からの読み取り（ハッシュタグ監視など）は未実装。README では API が月$200〜のためと説明

**安心設定と通報・ブロック**（`#t-sg`、`openReport` `REPORT_REASONS`）
- 同性のみ表示: マイページのトグル。標準の条件「性別」を「同性のみ」と「問わない」で切り替える
- 通報・ブロック: 人物シートとチャットのメニューから開く
  - 理由5種（転売・高額譲渡の勧誘、なりすまし、不快なメッセージ、ドタキャン、その他）と詳細（300字）
  - 「この人をブロックする」は初期状態でオン
  - ブロックすると: 公演の一覧から消える、届いた申請は見送り扱い、送った申請は削除、成立・トーク・当日メモも削除、開いているチャットは閉じる
- 金銭の扱い: 募集内容の編集画面とチャットの冒頭に「定価のみ」「金銭の受け渡しはアプリ内で扱わない」旨を表示

**マイページ**（`#s-me`、`renderMe`）
- プロフィールカードと集計（参戦回数・連番回数・ありがとう）
- ペンライトの色: アンバー／ピンク／ブルー／グリーン。アプリの差し色が変わる（`applyLight` が `<html>` の `data-light` 属性を変える）
- X連携（ユーザー名、募集文から取り込む）、相手の標準条件（「標準の条件を変える」）、安心設定
- プロフィール編集: 表示名（10字）、ハンドル（16字）、年代、性別、推し（複数）、現場スタイル（最大4つ、`STYLE_TAGS` 12種）、自己紹介（200字）
- 「使い方をもう一度見る」「デモをリセットする」（確認ダイアログのあと初期状態に戻す。初回案内は出さない）
- 右上のボタン（`#b-theme`）でライト／ダークを切り替える

**共通**
- `prompt()` / `confirm()` は使わず、アプリ内のシート（`askDialog`）で代用
- シートは右上の閉じるボタン、背景タップ、Esc キーで閉じる
- 通知は画面下のトースト（`toast`）

### データの保存

保存先は端末の localStorage だけ。

| キー | 中身 |
|------|------|
| `renban_demo_v3` | アプリの状態すべて（下の `S`）を JSON で保存。定数 `KEY` |
| `renban_demo_v3_theme` | ライト／ダークの手動設定（`light` / `dark`）。`KEY+'_theme'` |

- キー名は v3 のままだが、現行（v9.2）もこのキーを使っている。キーを変えると既存の利用者のデータは読まれなくなる
- 読み込み（`load`）は `defaultState()` に保存値を上書きする。一番上の階層だけを合わせるので、新しい項目を足すときは入れ子の中身に注意
- `S`（`defaultState`）の主な項目

| 項目 | 内容 |
|------|------|
| `me` | 自分のプロフィール（名前、ハンドル、年代、性別、エリア、推し、スタイル、自己紹介、連番回数、ありがとう数、Xユーザー名、ペンライトの色） |
| `attending` | 参戦予定。公演ID → `two` / `one` / `none`（チケット枚数） |
| `myTicket` | 自分の募集内容。公演ID → 席・受け渡し方法 |
| `sent` | 送った申請。`公演ID_ユーザーID` → 状態・日時・メッセージ |
| `incoming` | 届いた申請（初期2件） |
| `matches` | 成立した連番 |
| `chats` / `read` / `notes` | トーク、既読、当日メモ（キーは `公演ID_ユーザーID`） |
| `cond` | 条件。`default`（標準）と `byEvent`（公演ごと） |
| `homeFocus` / `homeView` / `onlyMatch` / `search` / `savedSearches` | 表示の設定、検索条件、保存した検索 |
| `diary` | 手帳の記録（初期2件：`p3` `p5`） |
| `done` | 終演処理した公演 |
| `unlocked` | デモで後から現れたユーザーの解放状態 |
| `notif` | お知らせ（最大30件） |
| `blocked` / `reports` | ブロックした相手、通報の内容（端末に残すだけ） |
| `onboarded` / `seenReq` | 初回案内の完了、申請タブを見たか |
| `schedAll` | 推しの予定を全件表示するか。`defaultState` には無く、押したときに追加される |

- 相手の「入力中」状態（`TYPING`）は保存しない

### 通信と外部リソース

- アプリのデータを外部に送る処理はない（`index.html` に `fetch` などの通信処理は無い。`fetch` を使うのは `sw.js` のキャッシュ処理だけ）
- 例外は利用者が X の「投稿」を押したとき。募集文を URL に入れて X の投稿画面を開く（送信は X の画面で本人が行う）
- 外部から読み込むもの
  - Google Fonts のスタイルシート（`fonts.googleapis.com`）。BIZ UDPGothic / Bricolage Grotesque / IBM Plex Mono。読めないときは端末の標準書体で表示される
  - CDN のスクリプトは使っていない
- X の投稿は Web Intent（`https://twitter.com/intent/tweet?text=...`）を新しいタブで開くだけ。API キーは使わない
- クリップボードへの書き込み（`navigator.clipboard`）は X 投稿文のコピーで使う
- サービスワーカーは同じサイト内のファイルだけを保存する。Google Fonts は保存しない

### 技術構成とコードの地図

**構成**
- ビルドなしの単一 HTML。フレームワークや外部ライブラリは使っていない
- `index.html` の中身は、`<style>`（見た目）→ 画面の HTML（`#app`）→ `<script>`（データと処理）の順
- `<script>` は `/* ================= 見出し ================= */` というコメントで区切ってある。この見出しで検索すると目的の処理にたどり着ける

**AIが最初に見る場所**
1. `README.md` の「状態」「デモの動き」「技術メモ」
2. `index.html` の `const KEY=` と `defaultState`（何を保存しているか）
3. `CONDS` `DEFAULT_COND` `PRESETS` `condFor` `scoreUser`（条件と一致率の中心）
4. 起動処理（`/* ================= 起動 ================= */`、ファイル末尾）

### PWA・iOS

**PWA（ホーム画面に追加して使う）**
- `manifest.json`: 名前「レンバン」、`start_url` は `./index.html`、`display` は `standalone`、縦向き固定、背景色・テーマ色 `#14122B`、アイコン 192px と 512px（512px は maskable 兼用）
- iPhone 用アイコンは `index.html` の `<link rel="apple-touch-icon">` で指定
- `sw.js`
  - キャッシュ名: `renban-v7`
  - 最初に保存するファイル: `./` `./index.html` `./manifest.json` `./icon-192.png` `./icon-512.png`
  - 取り出し方: 保存済みがあればそれを返す（キャッシュ優先）。無ければネットから取り、同じサイトのファイルなら保存する。オフラインで取れなければ `./index.html` を返す
  - 新しい版を入れたときは、古い名前のキャッシュを消す
- 登録条件: 表示中のホスト名が `github.io` / `localhost` / `127.0.0.1` のときだけ `sw.js` を登録する。Claude Artifact の中では登録しない
- README の使い方: iPhone の Safari で本番URLを開き、共有メニュー →「ホーム画面に追加」。全画面で起動し、オフラインでも動く

**iOSアプリ**
- 未着手。`ios-app/` フォルダは無い（`.gitignore` に `ios-app/www/` の行だけある）
- 社内提案の資料（`資料/プレゼン資料/gen.py` の「次のステップ」）では、Capacitor で包みプッシュ通知を足す計画。構成は `habit/ios-app/` と同じにする方針

**本番化に必要なこと（README「本番化する場合に必要なもの（未着手）」と社内提案の資料より）**
- サーバー: 認証、ユーザーDB、リアルタイムチャット（Supabase 等）
- 公演データの取り込み（チケットサイト連携か手動登録）
- 本人確認、通報の運営側の処理、「ありがとう」のサーバー集計
- チケットの金銭授受はアプリ内で扱わない（転売対策・法的リスク回避）
- 審査対応: アカウント削除、規約への同意、Sign in with Apple、プライバシーポリシー、サポートURL
- 申請: 資料では年齢制限 17+、プライバシーは「データを収集します」。フォルダ共通ルールの原則（4+・「データを収集しません」）とは違う。本番版はサーバーで利用者のデータを扱う計画のため、申請前に改めて確認が必要

### 既知の制限・注意点

**デモであることによる制限**
- 相手はすべて架空。申請の返事、トークの返信、ありがとうの返送は自動で、実在の人とはやり取りしない
- 当日メモ、通報、ブロック、ありがとうの「ひとこと」は自分の端末に残るだけ。相手や運営には届かない
- 本人確認、X連携（フォロワー数など）は固定値の見せかけ。マイページの X ユーザー名も表示に使うだけ
- 公演は埋め込みの21件だけ。新しい公演は増えない
- データは端末ごと・ブラウザごと。別の端末には引き継がれない
- ブロックを解除する画面は無い（解除するにはデモのリセット）
- エリア（`S.me.area`、初期値「関東」）を変える画面は無い

**README と実装の食い違い（実装を正とする）**
- README の「画面」表は初回案内を「3ステップ」と書いているが、実装は4ステップ（4枚目が初期設定）。同じ README の v9 の節は「4ステップ目」と書いており、表だけ古い
- README の「画面」表の「現場（これから）」に、v9 で足した「条件に合う人」「募集を X に出す」が載っていない
- README の初期設定の表は、女性を「同性のみ・本人確認済のみ・未成年除外」としている。実際は `DEFAULT_COND` の上に重ねるので、参戦3回以上・推し一致・物販一緒に並ぶ・声出し全力も効いている
- README は「ホームの順番を変える」と書いているが、実装では `homeFocus` が `people`（女性・回答しない）のとき、ホームの「募集を X に出す」は表示されない（公演ページの「投稿」は使える）
- README の手帳の説明「今年の参戦回数・費用合計」のうち、費用は今年分に限らず全記録の合計（画面の表示名は「記録した費用」）
- README は「データは localStorage のみ。通信なし」と書くが、起動時に Google Fonts を外部から読み込む
- README は「当日の段取りを共有」と書くが、デモでは共有されない（上記の制限のとおり）

**実装上の注意**
- 性別をマイページで変えて保存すると `applyPreset(m.gender,false)` が走る。標準の条件を自分で変えていても上書きされ、「連番が初めて」の条件も外れる。検索の並び順とホームの並び順も変わる
- 「同性のみ表示」トグルは標準の条件だけを変える。公演ごとの条件（`S.cond.byEvent`）には効かない
- `sw.js` のキャッシュ名は v7 のとき（コミット 18b2eae）から `renban-v7` のまま変わっていない。取り出しがキャッシュ優先のため、一度ホーム画面に追加した端末では、`index.html` を更新しても古い版が出続ける可能性がある。コードから読める動きで、実機では未確認
- サービスワーカーの登録失敗は `catch` されず、コンソールにエラーが出る。2026-09-15 の確認に使ったブラウザでは、`sw.js` を読みにいかずに登録が失敗した（ブラウザ側の制限か、未確認）
- README の Claude Artifact の URL は「v7・確認用」と書かれている。現行版との差は未確認
- localStorage のキー名 `renban_demo_v3` は版と一致していないが、変えると保存データが読まれなくなる
